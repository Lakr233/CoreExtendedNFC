Core API

The CoreExtendedNFC namespace exposes the high-level flows used by apps.

public static func scan(message: String? = nil) async throws -> (CardInfo, any NFCTagTransport, NFCSessionManager)
public static func scanAndDump(message: String? = nil) async throws -> (CardInfo, MemoryDump)
public static func dumpCard(info: CardInfo, transport: any NFCTagTransport) async throws -> MemoryDump
public static func readNDEF(info: CardInfo, transport: any NFCTagTransport) async throws -> NDEFMessage
public static func writeNDEF(_ message: NDEFMessage, info: CardInfo, transport: any NFCTagTransport) async throws
public static func readPassport(mrzKey: String, dataGroups: [DataGroupId], performActiveAuth: Bool) async throws -> PassportModel
public static func readTransitBalance(info: CardInfo, transport: any NFCTagTransport) async throws -> TransitBalance
public static func readSingaporeTransitBalance(transport: any ISO7816TagTransporting) async throws -> TransitBalance
public static func exportJSON(dump: MemoryDump, prettyPrinted: Bool = true) throws -> String

readTransitBalance supports Japan IC, Octopus, Singapore CEPAS, Korea KS X 6924, and China T-Union. Pass the original card information and transport from NFCSessionManager.scan; do not call refineCardInfo or use CoreExtendedNFC.scan, which refines automatically. FeliCa cards are routed by system code; ISO 7816 cards are probed for CEPAS, then KS X 6924 and T-Union. CEPAS communication, malformed-response, and history errors are propagated rather than treated as a different card family.

readSingaporeTransitBalance remains available for direct, read-only CEPAS purse and recent-log access. One traditional EZ-Link card has been read successfully on iPhone Air using this dedicated path; the integrated automatic scan, offline operation, comparison with a ticket-machine reference, and other card variants remain unverified on physical cards. SimplyGo history is unsupported. See the test guide.

Transit transaction migration

TransitTransaction.amount and balanceAfter change from Int to Int?. This is a source compatibility change: callers that read these properties must unwrap them. Existing initializer calls with integer values still work. A nil amount means the record has no recognized monetary amount; a nil balance means the source does not expose a post-transaction balance. Neither should be displayed or calculated as zero. Raw CEPAS records and their type codes remain available for inspection.

if let amount = transaction.amount {
    // Format in the card currency's stored unit.
    showAmount(amount)
}
if let balanceAfter = transaction.balanceAfter {
    showBalance(balanceAfter)
}

Existing JSON records containing numeric amounts and balances remain decodable. Encoding a nil value omits that key; JSON consumers must accept missing amount and balanceAfter keys. Numeric zero remains a known zero value.
