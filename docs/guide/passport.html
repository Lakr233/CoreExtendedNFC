Passport / eMRTD

Passport reading starts from the MRZ-derived key, establishes Secure Messaging with PACE or BAC, and reads LDS data groups from the eMRTD application.

Read Data Groups

// ICAO 9303 Part 11 Appendix D example: "L898902C<369080619406236"
let mrzKey = MRZKeyGenerator.computeMRZKey(
    documentNumber: "L898902C",
    dateOfBirth: "690806",
    dateOfExpiry: "940623"
)

let passport = try await CoreExtendedNFC.readPassport(
    mrzKey: mrzKey,
    dataGroups: [.com, .dg1, .dg2, .dg14, .dg15, .sod],
    performActiveAuth: true,
    trustAnchorsDER: cscaCertificates,          // DER CSCA certificates from your trust list
    onProgress: { message in print(message) }   // localized progress text
)

To read over a transport you already hold, for example from scan(pollingTargets: [.iso14443]), use the transport: overload. It runs the same workflow but neither updates the NFC sheet nor ends the session:

let (_, transport, manager) = try await CoreExtendedNFC.scan(pollingTargets: [.iso14443])
defer { manager.invalidate() }
let passport = try await CoreExtendedNFC.readPassport(
    transport: transport,
    mrzKey: mrzKey,
    trustAnchorsDER: cscaCertificates
)

The session-owning readPassport also accepts a manager: for your own NFCSessionManager or a subclass. To change how data groups are read, subclass PassportReader and override its open methods; see Subclassing.

Read Flow

  1. EF.CardAccess is read. When it advertises PACE, PACE runs first. If PACE fails, the reader falls back to BAC; a lost tag or cancelled task ends the read.
  2. EF.COM and EF.SOD are read first. A data group is selected when either lists it, and only the EF.SOD hash list can rule one out. When EF.COM is requested without EF.SOD and EF.COM omits a requested group, EF.SOD is read as the index too.
  3. DG1, then the other groups, DG15 and Active Authentication. EAC-protected DG3 and DG4 go last, so a chip that ends Secure Messaging on them cannot cost DG1, DG2, EF.SOD or AA.
  4. When Secure Messaging ends, the remaining groups are marked notRead and everything read so far is kept.

readPassport throws when nothing could be read, or when DG1 was requested but not read; DG1 is mandatory. Otherwise it returns a partial model. passport.dataGroupReadStatus explains each group: read, notPresent, unavailable (absent or protected), failed, or notRead. File sizes are capped at 10 MB for DG2-DG7 and 64 KB for the rest, so a corrupt length field cannot trigger huge reads. When the user dismisses the sheet, the error is NFCError.userCanceled; check error.isNFCCancellation to stay silent.

Security Report

passport.securityReport has one stage each for CardAccess, PACE, BAC, Chip Authentication, Passive Authentication and Active Authentication.

  • Passive Authentication is succeeded only when the hashes match, the EF.SOD signature verifies, and the Document Signer certificate (DSC) has a validated certification path to a CSCA in trustAnchorsDER. Without trust anchors, matching hashes and a valid signature are fallback. A bad signature, failed certification path validation or hash mismatch is failed.
  • Active Authentication is succeeded only when the chip signs the challenge, Passive Authentication is fully verified, and DG15 matches its hash in EF.SOD. A valid signature over an unauthenticated DG15 is fallback (ActiveAuthenticationStatus.verifiedUnauthenticatedKey), because a clone can carry its own key pair. A DG15 that does not match its hash is failed.

Re-check a saved model offline, for example after loading new CSCA certificates:

let result = passport.reverifyPassiveAuthentication(trustAnchorsDER: cscas)
let updated = passport.reverifyingSecurity(trustAnchorsDER: cscas)   // PA and AA re-judged

The status types are PassiveAuthenticationStatus (on passiveAuthResult) and ActiveAuthenticationStatus (on activeAuthResult); the DG15 key is an ActiveAuthenticationPublicKey. The 1.x names PassiveAuthStatus, ActiveAuthStatus and ActiveAuthPublicKey are deprecated typealiases.

Offline Models

To rebuild a model from data-group bytes you stored, for example in a file or database, use PassportModel(rawDataGroups:). It applies the reader's own parsers to EF.COM, DG1, DG2, DG7, DG11, DG12, DG14, DG15 and EF.SOD, and runs Passive Authentication unless performPassiveAuthentication is false. Passive Authentication verifies a CMS signature, so keep it off the main thread. Active Authentication needs the chip, so activeAuthResult is nil and the chip stages of the security report are skipped.

let model = PassportModel(
    rawDataGroups: savedDataGroups,     // [DataGroupId: Data], TLV-wrapped
    cardAccessRaw: savedCardAccess,     // optional
    trustAnchorsDER: cscas
)
print(model.mrz?.documentNumber ?? "-")

Current Scope

PACE (ECDH Generic Mapping on the NIST curves P-256, P-384 and P-521, MRZ password) is implemented with OpenSSL. It rejects a chip mapping or ephemeral public key that reflects the terminal's own key. Other PACE mappings and curves throw unsupportedOperation, and the reader falls back to BAC. BAC, Secure Messaging, data-group parsing, Passive Authentication and Active Authentication are implemented. Chip Authentication is read from DG14 but not performed, because its ECDH key agreement is not implemented; the stage reports notSupported when advertised.
