NDEF

CoreExtendedNFC routes NDEF reads and writes through the best family-specific path after tag identification.

Read

let message = try await CoreExtendedNFC.readNDEF(info: info, transport: transport)

A tag without an NDEF Capability Container (Type 2 CC0 other than E1h, Type 5 CC magic other than E1h / E2h, or no Type 4 NDEF application) throws NFCError.tagNotNDEFFormatted. A formatted tag without a readable NDEF TLV throws NFCError.ndefMessageNotFound. On Type 5 tags, readNDEF reads only the CC and the blocks covering the T5T area announced by MLEN, not the whole tag, so tags larger than 256 blocks can be read within blocks 0-255.

Write

try await CoreExtendedNFC.writeNDEF(message, info: info, transport: transport)

// Erase: a message with no records is written as an empty NDEF message.
try await CoreExtendedNFC.writeNDEF(NDEFMessage(records: []), info: info, transport: transport)

Records that cannot be encoded are refused before anything is written. An empty message is written as 03 00 FE on Type 2 and Type 5, NLEN = 0 on Type 4, and Ln = 0 on Type 3, which erases the tag.

  • Type 2: the CC on page 3 is read first. The tag must be NDEF formatted (CC0 = E1h, mapping major version 1) and grant write access, otherwise tagNotNDEFFormatted or tagLocked is thrown. Capacity is CC2 × 8 bytes, capped at the product's user memory. NTAG215/216 advertise less than their full user memory (CC2 3Eh / 6Dh).
  • Type 5: the CC is read first and must be formatted (E1h / E2h, major version 1, write access granted). The message is bounded by MLEN × 8 bytes. Blocks above 255 are read and written with the extended ISO 15693 commands; tags that reject them are limited to blocks 0-255. Only the blocks holding the NDEF TLV and its terminator are written; the CC and memory after the terminator are untouched.
  • Type 4: CC write access must be 00h. Both NLEN (T4T 2.0) and ENLEN (T4T 3.0) NDEF files are supported, up to 32 KB.

A message that does not fit throws NFCError.ndefCapacityExceeded(required:capacity:).

Format

formatNDEF(info:transport:) supports Type 2 and ISO 15693 tags; other families throw NFCError.tagNotSupported. Type 3 and Type 4 capability containers are managed by tag firmware. Type 2 formatting clears the user pages first and writes the CC (OTP) last. Type 5 formatting writes a fresh CC and an empty message across blocks 0-255.
