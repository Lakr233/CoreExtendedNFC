NDEF

CoreExtendedNFC routes NDEF reads and writes through the best family-specific path after tag identification.

Read

let message = try await CoreExtendedNFC.readNDEF(info: info, transport: transport)

A tag without an NDEF Capability Container (Type 2 CC0 other than E1h, Type 5 CC magic other than E1h / E2h, or no Type 4 NDEF Tag Application) throws NFCError.tagNotNDEFFormatted. A formatted tag without a readable NDEF TLV, or one holding an empty message (an erased tag: 03 00 on Type 2 / Type 5, NLEN = 0 on Type 4, Ln = 0 on Type 3), throws NFCError.ndefMessageNotFound on every family. On Type 5 tags, readNDEF reads only the CC and the blocks covering the T5T area announced by MLEN, not the whole tag. Blocks from 256 on are read with EXTENDED READ SINGLE BLOCK; if the tag rejects it, a message that ends past block 255 is reported as ndefMessageNotFound.

Write

try await CoreExtendedNFC.writeNDEF(message, info: info, transport: transport)

// Erase: a message with no records is written as an empty NDEF message.
try await CoreExtendedNFC.writeNDEF(NDEFMessage(records: []), info: info, transport: transport)

Records that cannot be encoded are refused before anything is written. An empty message is written as 03 00 FE on Type 2 and Type 5, NLEN = 0 on Type 4, and Ln = 0 on Type 3, which erases the tag.

Type 2, Type 4 and Type 5 writes follow the NFC Forum write procedure: the message length (TLV length or NLEN / ENLEN) is first written as zero, then the message, and the real length last, so a write interrupted by the tag leaving the field reads back as an empty message, never a truncated one.

  • Type 2: the CC on page 3 is read first. The tag must be NDEF formatted (CC0 = E1h, mapping major version 1) and grant write access, otherwise tagNotNDEFFormatted or tagLocked is thrown. Capacity is CC2 × 8 bytes, capped at the product's user memory. NTAG215/216 advertise less than their full user memory (CC2 3Eh / 6Dh). A message that fills the data area exactly is written without the optional terminator TLV. The NDEF TLV is written at the start of page 4; Lock Control and Memory Control TLVs, and the reserved areas they describe, are not preserved, which suits NXP Ultralight and NTAG tags whose lock and configuration bytes sit outside the user area.
  • Type 5: the CC is read first and must be formatted (E1h / E2h, major version 1, write access granted). The message is bounded by MLEN × 8 bytes. Blocks above 255 are read and written with the extended ISO 15693 commands; tags that reject them are limited to blocks 0-255. Only the blocks holding the NDEF TLV and its terminator are written; the CC and memory after the terminator are untouched. A tag whose CC requires the special frame format (CC byte 3 b4) is refused with unsupportedOperation, because CoreNFC cannot reliably send it.
  • Type 4: CC write access must be 00h. Both NLEN (T4T 2.0) and ENLEN (T4T 3.0) NDEF files are supported, up to 32 KB. When the card refuses the NDEF Tag Application D2760000850101, the mapping 1.0 application D2760000850100 is tried, and its files are then selected with P2 = 00h.

A message that does not fit throws NFCError.ndefCapacityExceeded(required:capacity:).

Format

formatNDEF(info:transport:) supports Type 2 and Type 5 (ISO/IEC 15693) tags; other families throw NFCError.tagNotSupported. The Type 3 Attribute Information Block and the Type 4 CC file are managed by the tag. Type 2 formatting clears the user pages first and writes the CC (OTP) last. Type 5 formatting writes a fresh CC and an empty message and clears the rest of the data area. On a tag with more than 256 blocks, the NDEF area covers the whole memory: the CC magic is E2h and blocks from 256 on are written with EXTENDED WRITE SINGLE BLOCK, once an extended read of the last block shows the tag accepts the extended commands. Otherwise, and on tags with 256 blocks or fewer, the area covers blocks 0-255 and the CC magic is E1h. Every block address is planned before the first write.
